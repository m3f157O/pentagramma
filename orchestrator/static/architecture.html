Architecture

How a sample becomes a verdict: telemetry in the guest → collection → detection engines → scoring → report. Planned components are marked.

1 · Guest VM (“pentagramma”, reverted to SANDBOX_READY per run)

Everything here is potentially visible to the sample — the guardian driver (planned) exists to defend and audit this layer.
MinHook monitor live37 Nt/Win32 hooks injected before the sample's first instruction; follows child processes (incl. WoW64). Emits argument-level API events over a named pipe.
Sysmon liveKernel-backed process/file/registry/network/DNS/injection events (EIDs 1–26). Survives direct syscalls and user-mode unhooking.
AMSI + PowerShell logging liveDeobfuscated script content (script blocks, scan results) — the main window into script-based stages.
Event logs liveSecurity / System / Defender channels, incl. AV detection names.
Environment dressing liveGolden image carries a believable used profile (documents, Edge history/bookmarks, RunMRU, recent shortcuts) so anti-sandbox checks see a real user. Uptime stays unfakeable (accepted).
SandboxGuard driver plannedProtects agent/Sysmon processes, keys and logs (documented Ob/Cm/minifilter callbacks); verifies hook integrity from kernel (unblindable); flags module remaps.
↑named pipe + merged telemetry.jsonl + artifacts, pulled via PSDirect / Copy-VMFile

2 · Collection

One normalized event shape per source, merged and time-sorted into a single stream; artifacts travel alongside.
telemetry.jsonlsysmon · apitrace · amsi · powershell · security/system/defender logs · guardian (planned)
Artifactspktmon PCAP · screenshots · interval process dumps · dropped files (hashed, YARA-rescanned)
↑executor: restore snapshot → boot → deploy agent → launch sample → collect

3 · Detection engines (single assembly path — live runs and offline replay share it)

Each engine emits alerts in one common shape; families are listed in evaluation order.
HeuristicsLOLBin patterns, burst/sequence detectors, Defender verdicts, dump/dropped-file YARA.
Behavioral signatures14 custom signatures over the API trace: injection chains, exec protection, APC, tokens, timing, tamper…
Blind-spot correlation liveApitrace↔Sysmon counterpart map: a Sysmon event with no hook counterpart = unhooking / direct syscalls. Silence detection for quieted traces.
Sigma2,082 vendored rules + customs over Sysmon events (min level medium).
CAPE community758 signature classes replayed over the API trace. Enrichment-only today (scoring off pending corpus validation).
YARA + capa (static)Pre-execution matching on the sample; capa capability extraction feeds scoring.
↑alerts → additive verdict score + MITRE coverage + IOC summary

4 · Scoring & output

VerdictAdditive score over scoring families with top-reasons attribution (benign / suspicious / malicious).
Report JSONEvents, alerts (sample vs environment scope), process tree, MITRE map, artifacts, verdict.
Dashboard + REST + MCPThis UI, the /api endpoints behind it, and the MCP server agents use to drive the sandbox.
↑every detection change is re-validated offline before it is trusted

5 · Validation & hardening loop

Offline replayscripts/replay_detection.py rebuilds a report's verdict from stored inputs with current code — drift isolation without re-detonation.
CanariesBenign BAT/PS1 pair must stay suspicious/37 with zero behavioral alerts; InjectionHarness must stay malicious/90.
Corpus metricsLabeled corpus with train/test splits drives precision/recall/FPR gates (detection_metrics.py).
Coverage map liveGenerated apitrace↔Sysmon counterpart table (docs/coverage-table.md) — the design basis for blind-spot detection.
Evasion resistance: the three tiers

A sandbox does not need to survive tampering — every run is disposable. It needs to see tampering, because “the sample unhooked ntdll at T+8s” is itself a top-tier signal. Investment is ordered accordingly:

TierGoalHowStatus
1 · SeeDetect tamperingApitrace↔Sysmon counterpart misses, silence detection, tamper flags on guarded-module writeslive
2 · SurviveKeep observing despite tamperingSandboxGuard driver: protects agent/Sysmon, config and logs; kernel-side hook-integrity verification (cannot be blinded from user mode)planned
3 · PreventBe invisible to the sampleHypervisor-level monitoring — deliberately out of scope (staying on Hyper-V, no public VMI API)rejected

Known, accepted blind spots: direct/indirect syscalls (only ETW-TI or a hypervisor sees them — ETW-TI is gated behind PPL signing; Sysmon still captures their kernel-level effects), and TLS-encrypted C2 content (capture is metadata-only).
